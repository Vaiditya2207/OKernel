## 2026-03-06 - Arbitrary File Write via Unsanitized Multipart Filename
Vulnerability Pattern: Unsanitized user input from `axum::extract::Multipart` (specifically `field.file_name()`) is concatenated directly to a directory path using `PathBuf::join`. This allows for path traversal (e.g., `../../../etc/passwd`) and absolute path overwriting (if the filename starts with `/`, `PathBuf::join` replaces the base path entirely).
Systemic Cause: The Rust standard library's `PathBuf::join` behavior combined with the Axum multipart extractor's lack of automatic filename sanitization creates a dangerous default when handling file uploads. Developers often assume `join` restricts the path to the base directory, which is incorrect for absolute paths or paths containing traversal sequences (`..`).
Auditor Note: In future scans of Rust codebases, prioritize auditing any usage of `std::path::PathBuf::join` or `Path::join` where the right-hand side is derived from user input, particularly from file uploads, archives, or web requests. Ensure strict sanitization (e.g., extracting only the file name component, rejecting paths with `..` or `/`) is performed before joining.
